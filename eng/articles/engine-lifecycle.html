AWEngine

Lifecycle and Errors

The Run(bool FastSplash = false) method manages the engine's full lifecycle, sequentially guiding the application through initialization, the main loop, and safe interception of potential crashes.

Execution Order

  1. Splash Screen (SplashScreen)
    Displays the engine's start screen. Behavior depends on the FastSplash parameter:

    • false (default): Displays the signature ASCII art, authorship info (AWEngine by revDevotee), and launches an animated loading spinner (-, \, |, /).
    • true: Skips the animation and ASCII art, displaying a short text string with a 1.5-second delay for a faster startup.

  2. Initialization (Init)
    Calls the protected abstract Init() method. At this stage, the child class is required to implement all necessary user-defined preparation (loading resources, creating starting entities, etc.).

  3. Main Loop (Update)
    Launches a continuous process within a while (running) block. Iterations run as long as the running flag is true. Modifying this flag from the outside allows for a graceful shutdown of the engine.

Critical Error Handling

The entire engine lifecycle (from the splash screen to the completion of Update) is wrapped in a protective try-catch block, preventing sudden application crashes without logging:

  • If any unhandled exception (Exception ex) occurs, the console is cleared (Console.Clear()).
  • The engine generates and prints a structured critical error report:
    • [SOURCE] — source of the error (assembly/module).
    • [TYPE] — full name of the exception class.
    • [MESSAGE] — error message.
    • [STACKTRACE] — detailed call stack trace.
  • Program execution is paused until the user presses any key (Console.ReadKey()), allowing them to review the crash details.
